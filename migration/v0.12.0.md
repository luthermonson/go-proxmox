# Migrating to v0.12.0

If you're upgrading from v0.10.x, read [v0.11.0.md](./v0.11.0.md) first.

Two themes, both the familiar "the Go type didn't match what PVE sends" kind:
decode fixes for fields PVE returns as 0/1 integers (they were typed `bool` and
either failed to decode or, for one, silently dropped data), and one more
backup-style option field made a pointer so `false` can be sent. All seven
changes are source-incompatible; if your code compiles against v0.12.0 you have
migrated.

## TL;DR

| Change | Affected callers | Section |
|---|---|---|
| `Cluster.CephFlag` now decodes PVE's `0`/`1` correctly; `CephFlag.Value` is `IntOrBool` (was `bool`) | callers reading `CephFlag.Value` (the `CephFlag(...)` method signature is unchanged) | [Ceph flags](#ceph-flags-decode-the-01-pve-sends) |
| `ContainerMigratePreconditions.Running` and `VirtualMachineMigratePreconditions.Running` / `.HasDBusVMState` are `IntOrBool` (were `bool`) | callers reading migrate preconditions | [Migrate preconditions](#migrate-precondition-booleans) |
| `ContainerMigratePreconditions.NotAllowedNodes` is `map[string]*ContainerMigrateNotAllowedNodes` (was a flat struct) | callers reading LXC migrate preconditions | [not-allowed-nodes](#lxc-not-allowed-nodes-is-keyed-by-node) |
| `FirewallNodeOption.NDP` and `FirewallVirtualMachineOption.NDP` are `*IntOrBool` (were `IntOrBool`) | callers that set `NDP` on firewall options | [Firewall NDP](#firewall-ndp-takes-a-pointer) |

Non-breaking, nothing to migrate: `Cluster.CheckID` now also recognises PVE
9.2's reworded "guest ID N is already in use" message (older PVE said "VM N
already exists"), so a taken VMID is reported as taken rather than surfacing an
error. See [New in v0.12.0](#new-in-v0120).

These correct bugs shipped in v0.11.0 (the migrate-precondition reshape and the
`CephFlag` return type) plus two pre-existing `bool` fields of the same class;
in every case the old type could not carry what PVE sends, so fixing your code
gets you data that previously failed to decode.

---

## Ceph flags decode the 0/1 PVE sends

`GET /cluster/ceph/flags/{flag}` and `/cluster/ceph/flags` return the flag state
as a `0`/`1` integer, not a JSON boolean. `Cluster.CephFlag` decoded straight
into a `bool`, which **errors** on `1`; `CephFlag.Value` had the same problem.

- `CephFlag` still returns `(bool, error)` — its signature is unchanged — but it
  now decodes through `IntOrBool`, so it works against a real server.
- `CephFlag.Value` is now `IntOrBool`. Read it with a `bool()` conversion:

```go
flags, _ := cluster.CephFlags(ctx)
if bool(flags[0].Value) { ... } // was: if flags[0].Value
```

`IntOrBool` accepts both `1`/`0` and `true`/`false`, so it is robust across PVE
versions.

## Migrate precondition booleans

PVE reports `running` (and, for VMs, `has-dbus-vmstate`) as `0`/`1` integers on
the migrate-precondition endpoints. These fields were `bool` and failed to
decode the `1`:

- `ContainerMigratePreconditions.Running` → `IntOrBool`
- `VirtualMachineMigratePreconditions.Running` → `IntOrBool`
- `VirtualMachineMigratePreconditions.HasDBusVMState` → `IntOrBool`

```go
pre, _ := vm.MigratePreconditions(ctx, "")
if bool(pre.Running) { ... } // was: if pre.Running
```

---

## LXC not-allowed-nodes is keyed by node

`GET /nodes/{node}/lxc/{vmid}/migrate` returns `not-allowed-nodes` as an object
**keyed by node name**, exactly like the qemu endpoint (which this library
already types as a map). v0.11.0 modelled it as a single flat struct, so a real
response decoded to an empty value and the per-node blocking-HA data was
silently dropped.

`ContainerMigratePreconditions.NotAllowedNodes` is now
`map[string]*ContainerMigrateNotAllowedNodes`:

```go
// before (v0.11.0)
pre.NotAllowedNodes.BlockingHAResources

// after (v0.12.0)
pre.NotAllowedNodes["node4"].BlockingHAResources
```

## Firewall NDP takes a pointer

`ndp` defaults to `1` on the node and guest `PUT .../firewall/options`
endpoints, and `0` is a valid value, but `FirewallNodeOption.NDP` and
`FirewallVirtualMachineOption.NDP` were plain `IntOrBool` with `omitempty`, so
`IntOrBool(false)` (the zero value) was dropped from the body and PVE kept NDP
on. Both are now `*IntOrBool`, the same "don't clobber PVE defaults" pattern as
the other firewall-option and backup-option pointer fields.

```go
// turn NDP off
_ = node.FirewallOptionSet(ctx, &FirewallNodeOption{NDP: Ptr(IntOrBool(false))})
```

`nil` keeps PVE's default; callers that set `NDP` to a value wrap it with
`Ptr(...)`.

## New in v0.12.0

Non-breaking:

- `Cluster.CheckID` recognises PVE 9.2's reworded parameter error "guest ID N is
  already in use" (older PVE: "VM N already exists"), matching on the typed
  `*APIError`'s `vmid` field. A taken VMID is reported as taken
  (`(false, nil)`) instead of surfacing the 400 as an error. No signature or
  contract change.
