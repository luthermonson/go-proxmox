# Migrating to v0.9.0

If you're upgrading from v0.7.x, read [v0.8.0.md](./v0.8.0.md) first.

## TL;DR

| Change | Affected callers | Section |
|---|---|---|
| `Task.Wait` / `WaitFor` return `*TaskFailedError` when the task fails | every caller that waits on a task | [Failed tasks are errors](#task-waits-report-failed-tasks-as-errors) |
| `WaitForCompleteStatus` also returns `*TaskFailedError` alongside `status == false` | callers that treat any `err != nil` as a transport error | [WaitForCompleteStatus](#waitforcompletestatus) |
| `"WARNINGS: n"` exit status is now a success (`IsSuccessful`, not `IsFailed`) | callers that read `IsFailed` / `IsSuccessful` after `Ping` | [Warnings](#warnings-are-a-success) |
| Waits return `ctx.Err()` as soon as the context is done | callers that relied on a wait finishing its current sleep first | [Context cancellation](#context-cancellation) |
| `Ping` no longer touches the `Is*` flags when the status request fails | callers that read the flags after a failed `Ping` | [Ping](#ping) |
| Non-2xx responses return a typed `*APIError`; statuses that used to be ignored now error | every caller | [Typed API errors](#typed-api-errors-apierror) |
| `AgentExecStatus.ErrTruncated` is `IntOrBool` and `Signal` is `int` (both were `bool`) | callers that read the agent exec status | [AgentExecStatus](#agentexecstatus-field-types) |
| Snapshot description updates always send `description` | callers that updated a snapshot with an empty `Description` | [Snapshot descriptions](#snapshot-descriptions) |
| `Node.Storage`, `(*Node).New` and `(*VirtualMachine).New` are deprecated | callers of those constructors (they still compile) | [Deprecated constructors](#deprecated-constructors-and-their-replacements) |

The first row and the typed-error row change behaviour without changing any
signature, so the compiler won't flag them. Read those sections even if your
code builds. The `AgentExecStatus` row is the only change that can stop code
from compiling.

New and opt-in, nothing to migrate: multi-endpoint failover
(`WithAdditionalEndpoints`, see [`examples/failover`](../examples/failover/)),
`Client.FindVirtualMachine` and `Client.FindContainer`, and `Node.StorageRef`.
They are covered under [New in v0.9.0](#new-in-v090).

## Task waits report failed tasks as errors

Before v0.9.0, `Task.Wait` and `Task.WaitFor` returned `nil` once the task
stopped running, whatever its exit status. A task that PVE reported as
failed, for example `VM quit/powerdown failed - got timeout` or
`VM 100 already running`, looked like a success unless the caller also
checked `task.IsFailed`. Callers that forgot treated a failed shutdown as done
and started the next operation against a VM in an unexpected state.

The waits now return a `*TaskFailedError` when the task finishes with any exit
status other than `OK` or `WARNINGS: n`:

```go
type TaskFailedError struct {
    UPID       UPID
    Node       string
    Type       string // e.g. "qmshutdown"
    ID         string // e.g. "100"
    User       string
    ExitStatus string // PVE's message, verbatim
}
```

`Error()` reads like
`task UPID:pve1:...: (qmshutdown 100 on pve1) failed: VM quit/powerdown failed - got timeout`.

```go
// before: the error only covered transport problems and timeouts, so the
// exit status had to be checked separately
if err := task.Wait(ctx, time.Second, 5*time.Minute); err != nil {
    return err
}
if task.IsFailed {
    return fmt.Errorf("shutdown failed: %s", task.ExitStatus)
}

// after: a failed task is an error
if err := task.Wait(ctx, time.Second, 5*time.Minute); err != nil {
    return err // *TaskFailedError, ErrTimeout, ctx.Err(), or an API error
}
```

The old `IsFailed` check still works. It is redundant now, but harmless.

To branch on the failure itself, use `errors.As` or `IsTaskFailed`:

```go
err := task.WaitFor(ctx, 120)

var tfe *proxmox.TaskFailedError
switch {
case errors.As(err, &tfe):
    log.Printf("%s %s on %s failed: %s", tfe.Type, tfe.ID, tfe.Node, tfe.ExitStatus)
case proxmox.IsTimeout(err):
    // still running after 120s
case err != nil:
    // couldn't read the task status, or ctx is done
}
```

### Code that deliberately ignored failures

If you start a task that is expected to fail sometimes and you only want to
know that it finished, filter the new error out:

```go
if err := task.WaitFor(ctx, 60); err != nil && !proxmox.IsTaskFailed(err) {
    return err
}
```

### Tasks PVE has forgotten

The status endpoint answers `no such task` once a task's status file has
gone, which can happen for old or rotated tasks. The waits used to return that
error. They now check the node's task index (`GET /nodes/{node}/tasks`) for the
task's final status and only return the original error if it isn't listed
there either. A failure found in the history is reported as a
`*TaskFailedError` like any other.

## WaitForCompleteStatus

`WaitForCompleteStatus` keeps its `(status, completed bool, err error)`
signature. For a failed task, `status` is still `false` and `completed` is
still `true`, but `err` is now a `*TaskFailedError` instead of `nil`:

```go
// before
status, completed, err := task.WaitForCompleteStatus(ctx, 30)
if err != nil {
    return err // only transport errors
}
if completed && !status {
    return errors.New("task failed")
}

// after — the same code still works, but the failure now arrives through err
// first. To keep both branches distinct, check for TaskFailedError:
status, completed, err := task.WaitForCompleteStatus(ctx, 30)
if err != nil && !proxmox.IsTaskFailed(err) {
    return err
}
```

## Warnings are a success

PVE reports `WARNINGS: n` as the exit status of a task that finished but
logged warnings, and counts it as a success. `Ping` used to set `IsFailed` for
it, because it only treated `OK` as success. It now sets `IsSuccessful`, the
waits return `nil`, and the count is available in the new `Task.Warnings`
field:

```go
if err := task.WaitFor(ctx, 300); err != nil {
    return err
}
if task.Warnings > 0 {
    log.Printf("%s finished with %d warning(s); see task.Log", task.UPID, task.Warnings)
}
```

`ExitStatus` still holds the raw `WARNINGS: n` string.

## Context cancellation

The waits used `time.Sleep` between polls, so a cancelled context was only
noticed at the next poll. `Wait`, `WaitFor`, `WaitForCompleteStatus` and the
`Watch` tail loop now wait on `ctx.Done()` and return `ctx.Err()`
(`context.Canceled` or `context.DeadlineExceeded`) immediately:

```go
ctx, cancel := context.WithTimeout(ctx, 2*time.Minute)
defer cancel()
err := task.Wait(ctx, 5*time.Second, 10*time.Minute)
if errors.Is(err, context.DeadlineExceeded) {
    // the context deadline (2m) fired before Wait's own max (10m)
}
```

`ErrTimeout` is still returned when `Wait`'s own `max` is reached first.

`Wait` also no longer pings the task twice before its first sleep. A
non-positive `interval` now falls back to `DefaultWaitInterval` (or one
second, should `DefaultWaitInterval` itself be set non-positive) instead of
busy-looping, and successive polls are always separated by a full interval
of quiet, even when a status request takes longer than the interval.

## Ping

`Ping` used to recompute `IsRunning` and the other flags even when the status
request failed, which left `IsRunning == true` on a task it had just failed to
read. On error it now returns the error and leaves the task as it was after
the last successful `Ping`. It also keeps the task's `UPID`, `Node`, `Type`,
`ID` and `User` if the status response leaves them out.

`Ping` still doesn't treat a failed task as an error. It only refreshes
state. Use `Wait` if you want the failure as an error.

## Nothing else

There are no other source-incompatible changes in task handling. New
exported identifiers: `TaskFailedError`, `IsTaskFailed`, `Task.Warnings`,
`TaskStopped`, and `TaskExitOK`.

## Refs and handle behaviour

`Client.NodeRef`, `Node.VirtualMachineRef` and `Node.ContainerRef` build
handles without any API request. Two existing methods change behaviour to
support them:

- `VirtualMachine.Delete` reads the VM's config first when the handle
  doesn't have one (a ref, or a VM from `Node.VirtualMachines` or the
  cluster resource list), to clean up a cloud-init ISO. That is one extra
  `GET`, and a token that may delete but not read the config
  (`VM.Allocate` without `VM.Audit`) now gets an error where the delete
  used to go through and leak the ISO.
- `Container.Ping` fetches the config as well as `status/current` (two
  requests instead of one), matching `VirtualMachine.Ping`.

The old `(*Node).New` and `(*VirtualMachine).New` constructors are
deprecated in favour of the refs.

## Typed API errors (`*APIError`)

Every non-2xx response now comes back as a typed `*APIError`, so callers
can classify errors with `errors.Is` / `errors.As` instead of matching on
`err.Error()`. No signatures changed. Five behaviours did:

| Change | Affected callers | Fix |
|---|---|---|
| Non-2xx statuses other than 400/401/403/500/501 (`404`, `502`, `595`, `596`, ...) now return an error. They used to fall through to JSON decoding and usually returned `nil`. | Code that relied on a 404 or proxy error being silently ignored | Check `proxmox.IsNotFound(err)` (or the other helpers) where a missing resource is expected |
| 401/403 return an `*APIError` instead of the bare `ErrNotAuthorized` value | `err == proxmox.ErrNotAuthorized` | `errors.Is(err, proxmox.ErrNotAuthorized)` or `proxmox.IsNotAuthorized(err)` |
| A 400 with a non-JSON body returns an `*APIError` instead of a JSON decoding error | Anyone matching on `invalid character ...` | `proxmox.IsBadRequest(err)` |
| The `Error()` text of a 500/501 may gain a `: <detail>` suffix when PVE's message spans more lines than the status line holds | Exact-equality comparisons on `err.Error()` | Use `strings.HasPrefix` / `strings.Contains`, or better, the helpers below |
| `IsNotFound(err)` is now true for PVE 500/400 responses whose message says a resource does not exist (it was only ever true for the sentinel before) | Code that already called `IsNotFound` after an API call | Errno-style messages ("No such file or directory") and storage-activation failures are excluded; see `notFoundPatterns` in errors.go for the exact matching |

### Classifying errors

```go
// before
if err != nil && strings.Contains(err.Error(), "does not exist") {
    // create it
}

// after
if proxmox.IsNotFound(err) {
    // create it
}
```

| Sentinel | Helper | Matches |
|---|---|---|
| `ErrNotFound` | `IsNotFound` | `404`, and PVE `500`/`400` messages saying a resource doesn't exist |
| `ErrNotAuthorized` | `IsNotAuthorized` | `401` and `403` (unchanged) |
| `ErrForbidden` (new) | `IsForbidden` | `403` |
| `ErrBadRequest` (new) | `IsBadRequest` | `400` |
| `ErrRateLimited` (new) | `IsRateLimited` | `429` |
| `ErrNodeUnreachable` (new) | `IsNodeUnreachable` | `595` / `596` |

For the details, use `errors.As` or the `AsAPIError` shortcut:

```go
if apiErr, ok := proxmox.AsAPIError(err); ok {
    fmt.Println(apiErr.StatusCode, apiErr.Message)
    for param, msg := range apiErr.Errors {
        fmt.Printf("  %s: %s\n", param, msg)
    }
}
```

### What `Error()` still prints

The text is kept so existing string matches keep working:

| Status | Before | After |
|---|---|---|
| 500 / 501 | `500 Configuration file '...' does not exist` | unchanged; a `: <rest of message>` suffix is added only when PVE's message has more than the status line shows |
| 400 | `bad request: 400 Parameter verification failed. - {"vmid":"..."}` | unchanged |
| 401 / 403 | `not authorized to access endpoint` | `not authorized to access endpoint: 403 Permission check failed (/vms/100, VM.Audit)` |
| other | usually no error | `404 Not Found`, `595 Connection refused`, ... |

### Retries

`WithRetry` is unchanged and still decides on the raw HTTP status at the
transport layer. When the retries run out, the last response becomes an
`*APIError`, so `apiErr.StatusCode` is the status of the final attempt.

## AgentExecStatus field types

`AgentExecStatus` now decodes `err-truncated` and `signal` the way PVE sends
them: `err-truncated` is a `0`/`1` integer, like `out-truncated` already was,
and `signal` is a signal number. Two field types changed, so code that treats
them as `bool` stops compiling:

```go
// before
if status.Signal {
    log.Println("killed by a signal")
}
var truncated bool = status.ErrTruncated

// after
if status.Signal != 0 {
    log.Printf("killed by signal %d", status.Signal)
}
truncated := bool(status.ErrTruncated) // IntOrBool is a bool type
```

`ErrTruncated` is an `IntOrBool`, the same type as `OutTruncated`, so
`if status.ErrTruncated { ... }` still compiles. Only assignments to a plain
`bool` and the `Signal` comparison need changing.

## Snapshot descriptions

PVE leaves a snapshot's description untouched when `description` is missing
from `PUT .../snapshot/{name}/config`. The `Description` field of
`VirtualMachineSnapshotUpdateOptions` and `ContainerSnapshotUpdateOptions` had
`omitempty`, so an empty value was dropped and a description could never be
cleared. It is now always sent:

```go
// before: a no-op, the description stayed
err := snap.UpdateConfig(ctx, &proxmox.VirtualMachineSnapshotUpdateOptions{Description: ""})

// after: clears the description
err := snap.UpdateConfig(ctx, &proxmox.VirtualMachineSnapshotUpdateOptions{Description: ""})
```

The code is the same. If you passed a zero-value options struct to mean "change
nothing", it now clears the description. Pass the current description, or don't
call `UpdateConfig`.

## Deprecated constructors and their replacements

These still compile and still work. They are marked `// Deprecated:` and will
show up in `staticcheck` / `golangci-lint`.

| Deprecated | Use | Why |
|---|---|---|
| `(*Node).New(c, name)` | `client.NodeRef(name)` | returns the handle instead of building a throwaway receiver |
| `(*VirtualMachine).New(c, node, vmid)` | `client.NodeRef(node).VirtualMachineRef(vmid)` | returns the handle instead of mutating one |
| `Node.Storage(ctx, name)` | `node.StorageRef(name)`, then `storage.Ping(ctx)` if you need the status fields | every `*Storage` method addresses the storage by node and name, so the status GET is only needed to read `Enabled`, `Avail`, `Total` and friends |

```go
// before: one GET for the node status, one for the storage status
node, err := client.Node(ctx, "pve1")
storage, err := node.Storage(ctx, "local")
content, err := storage.GetContent(ctx)

// after: GetContent is the only request
storage := client.NodeRef("pve1").StorageRef("local")
content, err := storage.GetContent(ctx)

// when you do want the status fields
err = storage.Ping(ctx)
fmt.Println(storage.Avail, storage.Total)
```

`client.Node(ctx, name)`, `node.VirtualMachine(ctx, vmid)` and
`node.Container(ctx, vmid)` are not deprecated. They still fetch, which is what
you want when you are going to read the data.

`Storage.Ping` is not `Storage.Status`. `Status` returns a separate
`*StorageStatus` from the directory-index path and leaves the handle alone;
`Ping` fills the handle.

## Smaller behaviour changes

None of these change a signature.

- **`VirtualMachine.AgentExec`** returns the API error when the request fails.
  It used to ignore it and report `no pid returned from agent exec command`.
  Code that matched on that text should check the typed error instead.
- **`VirtualMachine.Ping`** decodes into a fresh value and copies it over the
  handle only when both requests succeed, so a field PVE stops sending (`lock`
  once a VM unlocks) is cleared rather than left stale, and a failed `Ping`
  leaves the handle as it was.
- **`Task.Watch`** sends log lines in line order and runs to the end of the
  task. It used to range over a map, so lines arrived in random order, and it
  could stop before the last lines.
- **Request parameters** are built with `json.Number`, so an integer such as
  `1700000000` is sent as `1700000000` and not `1.7e+09`, and a nil pointer is
  left out instead of being sent as `<nil>`.
- **Uploads** send `content`, `checksum-algorithm` and `checksum` before the
  file part, which pveproxy requires.
- **`Storage.Backup`** fills `VolID` from the requested name when PVE leaves it
  out, so `Delete` keeps the directory part of names such as PBS's
  `vm/100/<timestamp>`.
- **Guest firewall IPSet deletes** (`DeleteFirewallIPSet`,
  `DeleteFirewallIPSetEntry`, on VMs and containers) send `force` and `digest`
  on the query string, where PVE reads them. They used to go in the request
  body.
- **`Node.VzTmpls`** results carry the client, node and storage, so `Delete`
  works on them.
- **`TermWebSocket`** closes its `recv` and `errs` channels only after its
  worker goroutines have exited, and closing twice is safe. A bad handshake
  reply returns an error instead of panicking. The close function no longer
  closes the `send` channel; it stays yours.

## New in v0.9.0

Opt-in additions. Nothing here changes existing code.

### Refs for node, VM, container and storage

```go
node := client.NodeRef("pve1")                 // no request
vm := node.VirtualMachineRef(100)              // no request
task, err := vm.Stop(ctx)                      // one POST

ct := node.ContainerRef(101)
storage := node.StorageRef("local")
```

A ref knows its node, VMID or storage name and nothing else. Actions work as
they are. `Ping` fills a ref with status (and config, for VMs and containers).
The accessors `IsRunning`, `IsStopped`, `IsPaused`, `IsHibernated` and `HasTag`
make no request and report `false` until `Ping` has run. See the
[README](../README.md#acting-on-a-node-vm-or-container-without-fetching-it-first)
and [`examples/vm-refs`](../examples/vm-refs/).

### One-call finders

When you know the VMID and not the node:

```go
vm, err := client.FindVirtualMachine(ctx, 100) // one GET /cluster/resources
if proxmox.IsNotFound(err) {
    // no QEMU guest with that VMID
}
task, err := vm.Reboot(ctx)

ct, err := client.FindContainer(ctx, 200)
```

The result is a ref bound to the node the cluster reported, so call `Ping` if
you want its status. `/cluster/resources` can lag by a few seconds, so a guest
created, migrated or destroyed a moment ago may resolve to a stale node or
not at all. Use it to route; the handle's own calls hit the owning node.

### Multi-endpoint failover

```go
client := proxmox.NewClient("https://pve1:8006/api2/json",
    proxmox.WithAPIToken(tokenID, secret),
    proxmox.WithRootCAFile("/etc/pve/pve-root-ca.pem"),
    proxmox.WithAdditionalEndpoints("https://pve2:8006/api2/json", "https://pve3:8006/api2/json"),
    proxmox.WithEndpointFailureThreshold(3),
    proxmox.WithEndpointCooldown(10*time.Second, 3*time.Minute),
)
```

Without `WithAdditionalEndpoints` the client behaves exactly as before. The
full rules are in the
[README](../README.md#multiple-endpoints-and-failover); a runnable program is
in [`examples/failover`](../examples/failover/).
