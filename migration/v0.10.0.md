# Migrating to v0.10.0

If you're upgrading from v0.8.x, read [v0.9.0.md](./v0.9.0.md) first.

## TL;DR

| Change | Affected callers | Section |
|---|---|---|
| `NodeStopAllOptions.ForceStop` is `*IntOrBool` (was `IntOrBool`) | callers that set `ForceStop` on `Node.StopAll` | [StopAll force-stop](#nodestopalloptionsforcestop-is-a-pointer) |
| `ClusterBackupOptions.Enabled`, `.Remove` and `.StdExcludes` are `*bool` (was `bool`) | callers that set any of these on `Cluster.NewBackup` or `ClusterBackup.Update` | [Backup job booleans](#clusterbackupoptions-enabled-remove-and-stdexcludes-are-pointers) |

Both changes are source-level breaks for the same reason, and the fix is the
same in both: wrap the value you were passing in `Ptr(...)`. If you never set
these fields, nothing changes — `nil` sends the same request the zero value
used to, and PVE applies the same default.

Nothing in this release changes behaviour without also changing a signature, so
if your code compiles against v0.10.0 you have already migrated.

---

## Why these fields became pointers

All four fields default to `1` (true) on the PVE side and are sent with
`omitempty`. As a plain `bool` / `IntOrBool`, the zero value (`false`) is
indistinguishable from "unset", so it was dropped from the JSON body and PVE
re-applied its default. You could not actually send `false`:

```go
// v0.9.0: the false is silently dropped, PVE keeps its default of 1
json.Marshal(&NodeStopAllOptions{ForceStop: IntOrBool(false), Timeout: 60})
// {"timeout":60}
```

Making them pointers follows the rule in `AGENTS.md`, "don't clobber PVE-side
defaults", and matches `BulkShutdownOptions.ForceStop`, which has been a `*bool`
since v0.7.0. The three states are now distinct:

- `nil` — omit the field, let PVE apply its default (what the old zero value did);
- `Ptr(false)` / `Ptr(IntOrBool(false))` — explicitly send `false`/`0`;
- `Ptr(true)` / `Ptr(IntOrBool(true))` — explicitly send `true`/`1`.

Use `Ptr` (already in the package) to take the address of a literal.

---

## NodeStopAllOptions.ForceStop is a pointer

`POST /nodes/{node}/stopall` hard-stops a guest after `Timeout` when
`force-stop` is `1`, which is PVE's default. Sending `force-stop=0` lets the
graceful shutdown time out instead of killing the guest. On v0.9.0 that was
impossible — the only non-default value was the zero value, which never reached
the wire.

```go
// before (v0.9.0) — compiles, but the false never reaches PVE
_, err := node.StopAll(ctx, &NodeStopAllOptions{
    ForceStop: IntOrBool(false),
    Timeout:   60,
})

// after (v0.10.0)
_, err := node.StopAll(ctx, &NodeStopAllOptions{
    ForceStop: Ptr(IntOrBool(false)), // now actually sends "force-stop": 0
    Timeout:   60,
})
```

Leaving `ForceStop` unset is unchanged: the field is omitted and PVE hard-stops
after the timeout, exactly as before.

## ClusterBackupOptions Enabled, Remove and StdExcludes are pointers

`Cluster.NewBackup` (`POST /cluster/backup`) and `ClusterBackup.Update`
(`PUT /cluster/backup/{id}`) share `ClusterBackupOptions`. Three of its fields
default to `1` on the PVE side:

- `Enabled` — whether the job runs on schedule;
- `Remove` — prune backups past the retention policy;
- `StdExcludes` — apply the standard exclude patterns.

On v0.9.0 you could not create a disabled job, keep old backups
(`remove=0`), or back up the standard excludes (`stdexcludes=0`): a `false`
marshalled to a body without the field, and PVE applied its default.

```go
// before (v0.9.0) — Enabled: false is dropped, the job is created enabled
err := cluster.NewBackup(ctx, &ClusterBackupOptions{
    Schedule: "daily 02:00",
    Storage:  "local",
    All:      true,
    Enabled:  false,
})

// after (v0.10.0) — the job is created disabled
err := cluster.NewBackup(ctx, &ClusterBackupOptions{
    Schedule: "daily 02:00",
    Storage:  "local",
    All:      true,
    Enabled:  Ptr(false),
})
```

Callers that previously set any of these to `true` only restated PVE's default,
so you can drop the field or write `Ptr(true)`; both send the same request as
before. All other `ClusterBackupOptions` fields are unchanged.
