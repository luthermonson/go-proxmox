# Migrating to v0.11.0

If you're upgrading from v0.9.x, read [v0.10.0.md](./v0.10.0.md) first.

This release is almost entirely decode fixes: fields and methods whose Go type
or JSON tag did not match what Proxmox VE actually returns, so they never
decoded correctly. Each change is source-incompatible, but in every case the
old shape could not carry the real value, so fixing your code gets you data you
were not getting before. A new schema drift tool (`cmd/apidrift`) and a weekly
CI job now flag this class of mismatch automatically.

## TL;DR

| Change | Affected callers | Section |
|---|---|---|
| `ClusterBackupOptions.IoNice`, `.LockWait`, `.StopWait`, `.Zstd` are `*uint` (were `uint`) | callers that set any of these on `Cluster.NewBackup` / `ClusterBackup.Update` | [Backup option pointers](#backup-option-fields-that-now-take-a-pointer) |
| `Cluster.CephFlag` returns `(bool, error)` (was `(string, error)`) | callers of `CephFlag` | [CephFlag](#clusterceph­flag-returns-bool) |
| `Container.Firewall` and `VirtualMachine.Firewall` removed, replaced by `FirewallSubdirs() ([]string, error)` | callers of either `Firewall()` | [Firewall → FirewallSubdirs](#firewall-is-now-firewallsubdirs) |
| `User.Tokens` is `UserTokens` (was `map[string]Token`) | callers reading the `Tokens` field | [UserTokens](#usertokens) |
| `NodeCertificate.NotAfter` / `.NotBefore` are `int64` (were `string`) | callers reading certificate validity | [Certificate times](#nodecertificate-times-are-int64) |
| `SDNZone.Pending` is `map[string]any` (was `bool`); `SDNZoneOptions.ExitNodesLocalRouting` is `IntOrBool` (was `bool`) | SDN zone callers | [SDN zones](#sdn-zone-fields) |
| `Disk.MountPoint` removed → `Disk.Mounted IntOrBool`; `Disk` is no longer comparable; `Disk.OSDIDList` added | callers reading `Disk`, or using `Disk` as a map key / with `==` | [Disk](#disk-mountpoint-mounted-and-comparability) |
| `ContainerMigratePreconditions` reshaped to the LXC schema | callers of container migrate preconditions | [Migrate preconditions](#containermigratepreconditions-reshaped) |

Everything else is additive — see [New in v0.11.0](#new-in-v0110). If your code
compiles against v0.11.0, you have migrated.

## Backup option fields that now take a pointer

Follow-up to the v0.10.0 change that made `Enabled`, `Remove` and `StdExcludes`
pointers. Four more `ClusterBackupOptions` fields have a non-zero PVE default
where `0` is a valid, meaningful setting, so as a plain `uint` with `omitempty`
a `0` was dropped from the body and PVE re-applied its default:

| field | PVE default | what `0` means |
|---|---|---|
| `IoNice` | 7 | highest best-effort I/O priority |
| `LockWait` | 180 | do not wait for the guest lock |
| `StopWait` | 10 | do not wait for the guest shutdown in stop mode |
| `Zstd` | 1 | use half of the available cores |

They are now `*uint`, matching `VirtualMachineBackupOptions`, which has used
pointers for these four fields all along. `nil` keeps PVE's default;
`Ptr(uint(0))` sends `0`.

```go
// before (v0.10.0) — the 0 is dropped, PVE keeps Zstd=1
err := cluster.NewBackup(ctx, &ClusterBackupOptions{Schedule: "daily 02:00", Zstd: 0})

// after (v0.11.0)
err := cluster.NewBackup(ctx, &ClusterBackupOptions{Schedule: "daily 02:00", Zstd: Ptr(uint(0))})
```

Callers that set these to a non-zero value wrap it the same way:
`IoNice: Ptr(uint(5))`.

## Cluster.CephFlag returns bool

`GET /cluster/ceph/flags/{flag}` returns a boolean. `CephFlag` returned it as a
`string`, so the caller got `""`/`"1"`-style values that did not match the
documented type.

```go
// before
v, err := cluster.CephFlag(ctx, "nobackfill") // v string

// after
set, err := cluster.CephFlag(ctx, "nobackfill") // set bool
```

## Firewall is now FirewallSubdirs

`(*Container).Firewall` and `(*VirtualMachine).Firewall` returned a `*Firewall`
decoded from `GET .../firewall`, but that endpoint is a directory index — a list
of sub-path names (`rules`, `aliases`, `ipset`, ...), not a firewall object — so
the decode never produced anything useful. Both methods are removed and
replaced by `FirewallSubdirs`, which returns the index as `[]string`. The same
method now also exists on `Cluster` and `Node`.

```go
// before — fw never carried meaningful data
fw, err := vm.Firewall(ctx) // fw *Firewall

// after
subdirs, err := vm.FirewallSubdirs(ctx) // subdirs []string, e.g. ["rules","aliases","ipset","options"]
```

The specific firewall calls (`GetFirewallAliases`, `GetFirewallIPSet`,
`GetFirewallRules`, ...) are unchanged.

## UserTokens

The `User.Tokens` field was typed `map[string]Token`, but `GET /access/users`
returns the token list as a JSON array while `GET /access/users/{userid}`
returns it as an object. The field is now a `UserTokens` type with a custom
`UnmarshalJSON` that accepts both shapes and normalises to a map, so field
access by token id still works.

```go
// before
var t map[string]Token = user.Tokens

// after
var t UserTokens = user.Tokens // still indexable by token id
```

The `GetAPITokens`, `APIToken`, `NewAPIToken`, `UpdateAPIToken` and
`DeleteAPIToken` methods are unchanged.

## NodeCertificate times are int64

`GET /nodes/{node}/certificates/info` returns `notbefore` and `notafter` as Unix
timestamps. They were typed `string`, so the values arrived unusable. They are
now `int64` with the correct `notbefore`/`notafter` tags.

```go
// after
cert := certs[0]
notAfter := time.Unix(cert.NotAfter, 0)
```

---

## SDN zone fields

- `SDNZone.Pending` was `bool` but PVE returns a nested object of pending
  changes. It is now `map[string]any`.
- `SDNZoneOptions.ExitNodesLocalRouting` is sent to PVE as a 0/1 boolean, so it
  is now `IntOrBool` (was `bool`), consistent with the other 0/1 option fields.
  Set it with `IntOrBool(true)`.

---

## Disk: MountPoint, Mounted and comparability

`GET /nodes/{node}/disks/list` returns `mounted` as a 0/1 flag, not a mount-path
string. The `Disk.MountPoint string` field is removed and replaced by
`Disk.Mounted IntOrBool`. A new `Disk.OSDIDList []int64` field carries the Ceph
OSD ids PVE returns as a list.

Because `Disk` now contains a slice (`OSDIDList`), **`Disk` is no longer a
comparable type**: you can no longer use `Disk` as a map key or compare two
`Disk` values with `==`. Compare the fields you care about instead.

```go
// before
if d.MountPoint != "" { ... }

// after
if bool(d.Mounted) { ... }
```

---

## ContainerMigratePreconditions reshaped

`GET /nodes/{node}/lxc/{vmid}/migrate` returns the LXC-specific precondition
shape, which differs from the VM one the type was modelled on. `LocalDisks` and
`LocalResources` are removed; `NotAllowedNodes` changes from
`map[string]*VirtualMachineMigratePreconditionsNotAllowedNodes` to
`*ContainerMigrateNotAllowedNodes`; a `DependentHAResources
[]MigrateBlockingHAResource` field is added. The VM-side
`VirtualMachineMigratePreconditions` is unchanged.

## New in v0.11.0

Additive, nothing to migrate:

- `Cluster.FirewallSubdirs` and `Node.FirewallSubdirs`, the cluster- and
  node-level counterparts of the method above.
- `Disk.Mounted`, `Disk.OSDIDList`, `ContainerMigratePreconditions.DependentHAResources`,
  `StorageContent.ApproximateSize`, and the new types `UserTokens`,
  `ContainerMigrateNotAllowedNodes` and `MigrateBlockingHAResource`.
- `Storage.Status` now targets `GET /nodes/{node}/storage/{storage}/status`
  (the bare path was a directory index), so the status fields decode.
- Schema return-type drift tooling: `cmd/apidrift` compares the library's
  mapped return types against the upstream PVE API schema and reports drift; a
  weekly GitHub Actions job runs it and opens a tracking issue when the schema
  moves. Maintainer tooling — it is not part of the client API.
